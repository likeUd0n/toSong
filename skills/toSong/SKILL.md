# テキスト・ファイルからの楽曲生成（toSong）

いきなり歌詞や設計書を書かず、**「種への還元（棚卸し）→ 絵（攪拌・偶然性）→ 観察・連想（絶縁）→ 戯曲・MV台本（実験）→ コンセプト・ペルソナ確定（結晶）→ 詩（マイニング・圧縮）→ 音（Style・歌詞）→ タイトル（最後）」** の順で構築する。

## 必須の設計原則
1. **発想（ランダム生成）では画像生成の前にコンセプトや観客視点を固めない**：断片やテーマから広げる場合は、先に言葉で結論を作ると絵も台本も「答え合わせ」になるため、核テーマ1つだけを握って絵を出し、偶然の違和感から物語を立ち上げる。（※具体的な体験談や資料など**文脈をそのまま歌にしたい場合は、ステップ 0 で「文脈モード」を選び直接ステップ 3 の台本へ渡す**）
2. **「観察・連想」と「仕様確定」を分け、間に戯曲・MV台本を挟む**：発想モードは画像＋抽選の種から、文脈モードは整理した登場人物・出来事から、いずれも4トラックの台本（`[映像]` `[音]` `[ト書き]` `[セリフ]`）へ合流させてキャラを動かす（実験）。コンセプト・ペルソナ・コア楽器は台本の後に抽出して確定する（結晶）。
3. **タイトルは最後に決める**：制作中は仮名で進め、絵・台本・歌詞が揃った最後の余韻から命名する（説明的なタイトルを避ける）。
4. **観客視点と心理モデル**：`Suno作曲メソッド.md` と心理学的観点（弱さ・矛盾・「私だけは理解できる」共感・先生視点の教訓）を組み込む。

## 制作パイプライン（全8ステップ）

> [!TIP]
> **確認ゲートの運用**
> 一気通貫の指定がない限り、**ステップ 1〜2（画像と連想メモ）** または **ステップ 3〜4（戯曲台本とコンセプト確定）** で一度ユーザーとイメージをすり合わせると手戻りを防げる。

### ステップ 0：入力の棚卸し ＆ ルート選択【還元】（仮フォルダで開始）
入力に何が含まれているか（どこが固定されているか）に応じて、次の 4 ルートから進め方を決める（いずれも **ステップ 3 の台本に合流** する）。

- **ルート A：断片・種モード**（断片的なテーマ・キーワード・感情の種から新しい物語を立ち上げたいとき）
  - 元テキストに含まれる情報・結論を一度手放し、核となるテーマ・感情の種を1つだけ選ぶ。1曲に収まらない要素（Not-To-Sing）は切り離す。
  - → **ステップ 1 → ステップ 2（完全ブラインド）→ ステップ 3** の順に進む。
- **ルート B1：要件・ブリーフ型**（CM・タイアップ・企画メモなど、守るべき方向性「範囲 X」はあるが物語や結末が未定のとき）
  - **範囲 X（目指す方向性）** と **NG 条件（世界観破綻・クライアント NG）** を定義する（枝葉は Not-To-Sing として切り離す）。
  - ステップ 1（画像生成）は任意。→ **ステップ 2（分離型観察・NG 除外フィルタ・抽選）→ ステップ 3** の順に進む。
- **ルート B2：体験談・日記型**（体験談・日記・チャット履歴など、出来事に加えて書き手の「感情の結論」まで書かれているとき）
  - 元テキストを **①物理的事実・登場人物・小道具・セリフ** と **②感情の結論**（「後ろめたさ」「寂しさ」等）に分解し、**②はステップ 3 終盤まで一時保留**する（枝葉は Not-To-Sing）。
  - ステップ 1（画像生成）は任意。→ **ステップ 2（分離型観察・NG 除外フィルタ・抽選）→ ステップ 3** の順に進む。
- **ルート B0：資料忠実パス**（設定密度が極めて高い資料や、余計な発散を足さず文脈どおりに作りたいとき）
  - 登場人物・関係性・出来事の流れ・キーとなるセリフや小道具を整理し、**ステップ 2 を完全スキップ**して直接 **ステップ 3** へ渡す。
- ※ 曲調の軸や BPM 帯はこの段階では決めない（ステップ 3〜4 の実験・結晶化を経てステップ 6 で決める）。
- **利用プランの確認**：Suno のプランが **無料版（Free）** か **有料版（Pro / Premier）** かを確認する（ステップ 8 の `suno-paste.md` 出力内容を絞るため）。
- 作業中は仮のフォルダ名（例：`~\Music\Suno\_draft_<日付>\`）で進める。

### ステップ 1：ビジュアルの変数的生成【攪拌】（ルート A 必須・B1 / B2 / B0 は任意）
`image-generator` サブエージェントでキービジュアルを **1〜2枚（空間・時間帯の対比）** 生成する。
- **画像に任せる領域**：季節感、光の色、偶然の生活の痕跡（小物や服装の矛盾）。プロンプトにはステップ 0 の核テーマと大枠のトーンだけを指定し、構図・感情・小道具はあえて余白（変数）を残す。
- **テキスト側へ逃がす領域**：間の時間経過、目に見えない五感、MV的なカメラワーク（主観POV・寄り引き）や音の変化は無理に何枚も生成せず、ステップ 2〜3 でテキスト補完する。
- **再生成の基準**：核テーマと全く噛み合わない絵が出た場合のみ 1 回だけ再生成可。ただし「予想外の違和感」はむしろ採用する。

### ステップ 2：観察 ＆ 連想メモ【絶縁】（ルート A / B1 / B2｜B0 はスキップ）
詳細は [story-guide.md](references/story-guide.md) を参照。元テキストの思い込み（重力）や LLM の「都合のいい足し算」「ベタな連想」を断ち切り、次の台本へ発散の種を渡す。**ここではまだ時間軸・五感・キャラ設定・コンセプトを確定させない。**
1. **テーマ非公開の観察（日常語 A/B バケツ列挙）**：元テキストや範囲 X・核テーマを渡さない別コンテキスト（サブエージェント等）を使い、**バケツ A（馴染みの軸：5〜8個）** と **バケツ B（日常の細部：5〜8個）** を解釈を交えず列挙する。
   - **ルート A**：ステップ 1 の画像だけを見せる。
   - **ルート B1 / B2**：ステップ 1 で画像を生成した場合は画像だけを見せる。画像がない場合は、範囲 X や感情語・固有名詞・比喩を伏せた**「時間・場所・物理状態」の 3 点**だけを渡す。
2. **NG 除外フィルタ（B1 / B2 のみ）**：メイン側で、**範囲 X の NG 条件・世界観破綻に抵触する要素だけ**をブラックリスト方式で除外する（好みの要素だけ残す加点選別はしない）。
3. **プログラム乱数による強制抽出 ＆ 引き算**：[pick_motifs.py](scripts/pick_motifs.py) を使い、**バケツ A から 1 個・バケツ B から 1 個をランダムに強制抽出**する。ルート A では選ばれなかった残りの要素を次工程で使用禁止にする（B1 / B2 では文脈上の必須要素を消さないため使用禁止は強制しない）。
4. **テーマ接続 ＆ 連想ジャンプ（カメラマンの着眼点）**：ここで初めて核テーマや範囲 X と抽選された `[A, B]` を突き合わせ、「なぜこの 2 つが結びつくのか」という着眼点から、**事象→記憶への連想**や**解決しない矛盾・ジレンマ**を切り取る（B2 で一時保留した感情の結論は、ステップ 3 の終盤〜ステップ 4 で再接続する）。

### ステップ 3：戯曲・MV台本の執筆【実験】（`script.md`）
詳細は [story-guide.md](references/story-guide.md) を参照。
- **歌や歌詞の都合・事前設定を一度すべて忘れる**（1番・2番・サビの構成や文字数制限を意識しない）。
- **3〜4シーン、場所は1〜2か所**程度の短い一幕劇として、各シーンを **`[映像 / カメラ]` `[音 / 環境]` `[ト書き]` `[セリフ / 心の声]`** の4トラックで自由に動かす。
- 心理を地の文で説明せず、カメラの距離・視線（POV・インサート）、環境音の切り替わり、身体の動きと言葉のギャップ（本音の矛盾）で表現する。

### ステップ 4：設計の確定【結晶】（`concept.md` / `ペルソナ.md`）
詳細は [story-guide.md](references/story-guide.md) を参照。ステップ 1〜3（画像と台本）の実験で一番強く立ち上がった芯を抽出し、後半工程がブレないよう言語化・固定する。
1. **コンセプト ＆ 観客視点の確定**：台本で起きた感情の動きから、**曲のコンセプト**と**観客視点（聴き終えたリスナーにどうなってほしいか）**を定義する。
2. **時間軸・周囲の音の流れ・五感の整理**：台本内の時間進行・環境音の変化、および五感（**触覚は必須**、嗅覚・味覚は1点スパイス）を整理する。
3. **コア楽器・キャラクター化されたペルソナ確定**：立ち上がった空気感からコア楽器（3〜4点）を決め、外に見せる自分（強がり・役割）と内側の本音（弱さ・願い）を抱えたキャラクターを `ペルソナ.md` に確定する。

### ステップ 5：ワード・マイニング ＆ 詩的圧縮（台本 → 詩の骨格）
詳細は [lyrics-guide.md](references/lyrics-guide.md) の「1. テキストマイニングと詩的圧縮」を参照。いきなり歌詞の文字数合わせに入らず、まず台本を「詩」に変換する。
1. **ワード・マイニング（全体調和の土台 ＋ スパイス ＋ 行動の理由）**：元テキスト・`ペルソナ.md`・`script.md` から語を抜き出し、**「モノのコア名詞（3〜4個）」** と **「環境の時計（2〜3個）」** で全体調和の土台を作りつつ、予定調和を崩すフックとして **「スパイス・キーワード（1〜2個）」** を意図的に選び取る。あわせて、**「行動の理由（心理のフック・1文）」**をピン留めし、次工程で削り落とさないようにする。
2. **感情フィルター（比喩の反転 ＆ ジレンマの同居）**：同じ物理モチーフ・五感が「不安／停滞時（1番）」と「回復／納得、または矛盾を抱え込んだまま（サビ）」でどう見えるかを定義する。
3. **自由詩の執筆（`poetry.md`：制約を外してインスパイアのまま書く）**：台本の要約・補完にせず、連想ジャンプ・ジレンマ・スパイスを起点に**純粋な「詩」として好きに書き切る**。その豊かな表現の中から、ステップ 7 で歌に合うフレーズを選び取る。

### ステップ 6：Style of Music の生成（`genStyle` スキル）
`../genStyle/SKILL.md` を読み、ステップ 4 で確定したコア楽器・音の流れ、およびステップ 3（`script.md`）の `[音 / 環境]` の緩急をもとに `styles.txt` を作成する。

### ステップ 7：詩の骨格から歌詞への翻訳（`<曲名>.txt`）
詳細は [lyrics-guide.md](references/lyrics-guide.md) を参照。**優先順位は「①意味・因果 ＞ ②自然な日本語 ＞ ③音数・母音」**とし、音数合わせのために主語・述語や行動の理由を削らない。
1. **ラスサビ先作り ＆ セクション展開**：まず心臓部となる**ラスサビの決めフレーズ（母音ライム・開口母音・スパイス）**を最初に作り、そこから逆算して1番→2番→Cメロを配置する（全体のコア名詞を増やさず視点・見え方を変えて回収しつつ、スパイスをフックとして効かせる。Cover / Persona 展開用にラスサビ単体を先に試すのも可）。
2. **音数グリッド・歌唱音韻設計**：BPM に合わせたモーラ数（固定値ではなくレンジの幅で調整）・ブレス位置・強拍の母音ライム・高音の開口母音（`a, e, o`）を設計。
3. **2段階監査（意味・文脈監査 → モーラ・譜割り監査）**：まず台本を知らない読者目線で「何をしていて、なぜそうしているか」「主語・述語が揃っているか」を監査し、通った後にひらがな＋小節線 `/` に展開してモーラ・ブレス位置を監査する。
4. **Suno メタタグ・発音ガード**：`[Tag]`（1〜2語・行分け）、難読漢字のひらがな開き、数字・略語のカタカナ固定、カギ括弧 `「 」` と読点 `、` の除去。

### ステップ 8：タイトルの命名 ＆ 一貫性チェック・整理
- **最後にタイトルを決める**：完成した画像・物語・詩・歌詞の全体を見渡し、説明的にならない**象徴的・余韻の残るタイトル**を命名する。
- **タイトル一貫性（バックリンク）チェック**：決めたタイトルが示す核のイメージや時間軸が、ラスト1行だけでなく **1番・2番・サビのすべてで伏線として鳴っているか** を確認し、必要なら1番の描写に微調整を入れる。
- **貼り付け用データと制作データの分離**：
  - プロジェクトルート（`~\Music\Suno\<曲名>\`）には **Suno へそのままコピペできる貼り付け用ファイルだけ** を置く。
    - **無料プラン共通**：`title.txt`（Title）、`style.txt`（Style of Music）、`lyrics.txt`（Lyrics）
    - **有料プラン（Pro/Premier）追加**：`exclude.txt`（Exclude Styles）、`settings.txt`（Style Influence / Weirdness 等）
    - **ワンクリックコピペ用まとめ**：`suno-paste.md`（無料プラン用・有料プラン用に見出しを分け、各欄をコードブロックで囲んで1ファイルからすぐコピーできる形式にする）
  - 制作過程のデータ（`script.md`, `ペルソナ.md`, `poetry.md`, `visual_*.png/jpg`, `review.md`, 過去バージョン等）は **`work\` サブフォルダ** にまとめる。
- ユーザーに一式を報告し、仕上げのブラッシュアップとして **`/song-review`** を提案する。
