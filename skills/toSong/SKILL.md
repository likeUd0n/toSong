# テキスト・ファイルからの楽曲生成（toSong）

**「還元（ステップ0）→ 絵（1）→ 観察・連想（2）→ 台本（3）→ 設計確定（4）→ 詩（5）→ Style（6）→ 歌詞（7）→ タイトル・カバー・整理（8）」** の順で構築する。

## 必須の設計原則
1. **発想時は絵より先に結論を固めない**：核テーマ1つだけを握って絵を出し、偶然の違和感から物語を立ち上げる（体験談や資料どおりに作る場合はステップ 0 でルートを選ぶ）。
2. **「観察」と「設計確定」の間に戯曲・MV台本（4トラック）を挟む**：歌の都合を忘れてキャラを動かし、その後でコンセプト・ペルソナを結晶化する。
3. **タイトルとカバー画像は最後に作る**：制作中は仮フォルダで進め、歌詞・音が揃った最後の余韻から命名し、ジャケット画像 `cover.jpg` を生成する。

## 制作パイプライン（全8ステップ）

> [!TIP]
> 一気通貫の指定がない限り、**ステップ 1〜2** または **ステップ 3〜4** でユーザーとイメージをすり合わせると手戻りを防げる。

### ステップ 0：入力の棚卸し ＆ ルート選択【還元】
入力に応じて進め方を選ぶ（いずれも **ステップ 3** へ合流する）。曲調や BPM はこの段階では決めない。

- **ルート A（断片・種）**：テーマやキーワード1つだけを選び、他は切り離す → **ステップ 1 → 2（完全ブラインド）→ 3**
- **ルート B1（要件・ブリーフ）**：**範囲 X（方向性）** と **NG 条件** を定義（画像生成は任意）→ **ステップ 2（NG除外・抽選）→ 3**
- **ルート B2（体験談・日記）**：**①物理的事実・小道具・セリフ** と **②感情の結論** に分け、②はステップ 3 終盤まで保留（画像生成は任意）→ **ステップ 2（NG除外・抽選）→ 3**
- **ルート B0（資料忠実）**：登場人物・出来事・小道具を整理し、**ステップ 2 をスキップ**して **ステップ 3** へ直行

**利用プランの確認（記憶つき）**：
- `~/.config/toSong/preferences.json`（例：`{"plan": "free"}`）を確認し、すでに `"plan"`（`"free"` / `"paid"`）が記録されていれば確認せずそのまま使う（ユーザーから変更の指定があったときのみ更新）。
- 未設定の場合のみ「無料版（Free）か有料版（Pro / Premier）か」を聞き、回答を `~/.config/toSong/preferences.json` に保存する。

### ステップ 1：ビジュアルの変数的生成【攪拌】（A 必須・B1/B2/B0 は任意）
キービジュアルを **1〜2枚（対比）** 生成し、仮フォルダの `work/visual_1.jpg`（2枚目は `work/visual_2.jpg`）に保存して目視確認する。
- **手段の優先順位**：① `cf-image` MCP（`generate_image`、英語プロンプト・`steps: 4`）→ ② `image-generator` サブエージェント（不可時は B1/B2 同様の物理3点テキストで代用）。
- **余白を残す**：核テーマと大枠のトーンだけを指定し、構図や感情の細部は決め込まない（再生成は噛み合わない場合のみ1回まで、最大3枚）。

### ステップ 2：観察 ＆ 連想メモ【絶縁】（A / B1 / B2｜B0 はスキップ）
詳細は [story-guide.md](references/story-guide.md) を参照。
1. 元テキスト・核テーマ・感情結論を伏せた別コンテキストで、**バケツ A（馴染みの軸：5〜8個）** と **バケツ B（日常の細部：5〜8個）** を日常語で列挙する。
2. B1/B2 のみ NG 条件に反する要素をブラックリスト除外する。
3. [pick_motifs.py](scripts/pick_motifs.py) で **A から 1 個・B から 1 個** を乱数抽出し、テーマと突き合わせて記憶への連想・ジレンマを切り取る。

### ステップ 3：戯曲・MV台本の執筆【実験】（`script.md`）
詳細は [story-guide.md](references/story-guide.md) を参照。歌や文字数を忘れ、**3〜4 シーン（場所 1〜2 か所）** の短い一幕劇として **`[映像 / カメラ]` `[音 / 環境]` `[ト書き]` `[セリフ / 心の声]`** の4トラックで書く。

### ステップ 4：設計の確定【結晶】（`concept.md` / `ペルソナ.md`）
詳細は [story-guide.md](references/story-guide.md) を参照。台本から立ち上がった芯をもとに、コンセプト・観客視点（`concept.md`）、時間軸・音の流れ・五感（触覚必須＋嗅覚/味覚1点）、コア楽器（3〜4点）と濃いキャラクター（`ペルソナ.md`）を確定する。

### ステップ 5：ワード・マイニング ＆ 詩的圧縮（`poetry.md`）
詳細は [lyrics-guide.md](references/lyrics-guide.md) を参照。コア名詞（3〜4個）・環境の時計（2〜3個）・スパイス（1〜2個）・行動の理由（1文）を抜き出し、感情フィルター表を作った上で、制約を外した自由詩 `poetry.md` を書く。

### ステップ 6：Style of Music の生成（`genStyle` スキル）
`../genStyle/SKILL.md` と [Suno作曲メソッド.md](references/Suno作曲メソッド.md) を参照し、`styles.txt` を作成する。

### ステップ 7：歌詞への翻訳 ＆ 2段階監査（`lyrics.txt`）
詳細は [lyrics-guide.md](references/lyrics-guide.md) と [Suno作曲メソッド.md](references/Suno作曲メソッド.md) を参照。
**優先順位：①意味・因果 ＞ ②自然な日本語 ＞ ③音数・母音**
- ラスサビの決めフレーズから逆算して構成し、**第1関門（意味・文脈監査）→ 第2関門（モーラ・譜割り監査）** の順で監査する。
- Suno メタタグ・表記ガード（読点・カギ括弧なし、多音字ひらがな、数字・略語カタカナ）を適用する。

### ステップ 8：タイトル・カバー画像・整理
1. **タイトル命名 ＆ 一貫性チェック**：全体を見渡して余韻の残るタイトルを決め、タイトルの核イメージが1番〜サビすべてと繋がっているか確認する。
2. **カバー画像生成（`cover.jpg`）**：タイトル・コンセプト・曲の空気感を反映したジャケット画像（文字・ロゴなし）を、ステップ 1 と同じ手段で曲フォルダ直下に `cover.jpg` として 1 枚生成する（ユーザーが不要と指定した場合のみ省略）。
3. **貼り付けファイル生成 ＆ フォルダ整理（`~/Music\Suno\<曲名>\`）**：
   - **`work/` サブフォルダ**：`title.txt`, `style.txt`, `lyrics.txt`（有料プラン時は `exclude.txt`, `settings.txt` も）、および `script.md`, `concept.md`, `ペルソナ.md`, `poetry.md`, `styles.txt`, `visual_*.jpg`, `review.md` 等の中間・履歴ファイルを保存する。
   - **貼り付け用ファイル生成**：[generate_paste.py](scripts/generate_paste.py) を実行（`python scripts/generate_paste.py "<曲フォルダ>"`）し、ルート直下に **`suno-paste.md`** と **`suno-paste.html`**（コピーボタン付き）を生成する（上から **Lyrics → Style of Music → Title** の順）。
   - **ルート直下（貼り付け用・ジャケットのみ）**：`suno-paste.md`、`suno-paste.html`、`cover.jpg`
4. 完了報告では、まず **[`suno-paste.html`](suno-paste.html) へのクリック可能なリンク（`file://`）を提示してブラウザで開くよう誘導し**（コピーボタンで上から順に Suno へ貼り付け可能）、仕上げのブラッシュアップとして **`/song-review`** を提案する。
